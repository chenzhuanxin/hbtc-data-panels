企业投递简历采集面板

从一家企业出发，把「发布了哪些岗位 · 谁投了简历 · 简历里写了什么」一次拿全
端口 8790 Flask + BeautifulSoup 简历全量内容 单表多页 Excel Windows 单文件 exe

这个工具是做什么的

输入一个企业名称（支持模糊），它会顺着招聘后台的链路一路走到底，把投递简历和简历正文整成一份 Excel。

招聘后台里，想知道「某企业收到了哪些投递、投递人是什么背景」，需要手工点开企业 → 岗位 → 投递列表 → 每份简历详情， 几百份简历点下来非常费时。这个面板把整条链路自动化：企业名称模糊搜索 → 拿到企业账号 → 拉取该企业全部岗位 → 逐个岗位拉取投递简历列表 → 再逐份抓取完整简历详情 → 汇总导出。

企业名称→ 企业账号→ 岗位列表→ 投递简历→ 简历详情→ Excel
  • 企业模糊搜索：输入「宝顺」「物流有限公司」这类关键词即可命中，不用完整全称。
  • 岗位列表可单独用：选定企业后可以先只看它发布了哪些岗位、每个岗位收到多少投递。
  • 投递明细：投递人姓名、投递时间、电话 / 邮箱 / QQ（这里电话是明文，无需 OCR）。
  • 简历深度解析：基本信息、期望职位与薪资、自我描述、工作经历、教育经历、语言能力、证书、头像照片。
  • 导出可勾选：只要岗位列表 / 只要投递简历 / 两者都要，三种组合任选，文件名自动区分。
  • 投递列表并发抓取：岗位投递用线程池（默认 6 线程）。
  • 简历详情限速抓取：前台简历页有站点反爬，默认 1 请求/秒，命中拦截自动熔断。

接口链路（全部实测可用）

登录后台 Cookie 即可，无需前端网站 Cookie。四个关键接口串起整条流程。

环节接口说明
① 企业模糊搜索 GET /Enterprise/GetCompanyListData
?keyword=关键词&keyType=1&openSource=0		 keyType=1 才是模糊搜索；keyType=0 表示不筛选，会返回全量企业
② 岗位列表 GET /Post/GetYZJobList?key={企业username} 兼职岗位走 /Post/GetJZ_YZJobList
③ 岗位投递简历 GET /Post/GetSendJlList
?jobid={岗位id}&istj=-1&infotype=1		 分页返回：投递人、时间、电话、邮箱、QQ、姓名、简历ID
④ 简历详情 GET www.hbtc.ccoo.cn/post/qiuzhi/{jlid}x.html 前台简历详情页，服务端渲染完整简历，需前台登录 Cookie；字段最全
为什么简历内容要从前台页取？ 后台编辑页 /Post/JlEdit 只能拿到一部分字段（且部分简历该表单为空）， 拿不到「工作经历 1-10 / 教育经历 / 语言能力 / 获得证书 / 职位类别 / 现居地」等完整内容。 完整简历内容只在前台简历详情页上，该页必须带前台登录 Cookie （不带 Cookie 会返回登录页，约 22 KB，无简历内容）。 所以面板里把「后台 Cookie」和「前台 Cookie」分开配置，各管一段。

简历全量数据是怎么拿到的

一条链路：投递列表给你「谁投了」，前台简历页给你「这个人是谁、干过什么」。

  • 后台 Cookie：用于企业搜索、岗位列表、投递简历列表。
  • 前台 Cookie：用于逐份打开 /post/qiuzhi/{jlid}x.html 解析完整简历。
  • 前台 Cookie 怎么取：浏览器登录 www.hbtc.ccoo.cn → F12 → Network → 任意请求 → 复制 Request Headers 里的 Cookie 整串，粘到面板①「前台 Cookie」框， 点「测试前台 Cookie」验证。
  • 失效表现：所有简历都返回登录页。此时面板会提示，且本轮简历详情退化为后台页的部分字段。 重新登录复制新 Cookie 即可。
  • 限速（重要）：前台简历页前方是 nginx WAF，高频访问会返回带滑动验证的 403 并临时拉黑本机 IP。 因此前台简历详情默认 1 请求/秒（front_rate = 1.0），在途连接上限 2； 连续 3 次被拦截就自动熔断停止剩余任务。按此速率，500 份详情约 8 分钟、100 份约 2 分钟。 把「前台请求间隔」调小会更快，但要自负被封风险。

解析要点

  • 姓名优先取 PC 区块的 <div class="j-name"><h1>，避免把性别标签混进姓名。
  • 年龄 / 性别 / 学历 / 工作经验 / 现居地 依次取 div.j-pos 内的第 1–5 个 <span>。
  • 工作经历、教育经历、语言能力、获得证书 必须限定在各自区块内解析——四个区块用的是同一套 j-work-module clearfix step-circle 类名，直接对整页匹配会把证书/语言项误当成工作经历。
  • 工作内容里的 <br/> 会转成换行后再写入单元格。
  • 头像的默认占位图（offer-list-autor*.png）会被识别并视为空。
  • 证书与语言项取不到名称时直接不收录，避免写入占位假数据。

使用流程

① 填两种 Cookie

「Cookie」填后台（管企业/岗位/投递列表）；「前台 Cookie」填前台站点（管完整简历内容）。各自点「测试」验证。

② 搜索企业

输入企业名称关键词做模糊搜索，从结果里选中目标企业。

③ 取岗位列表

可选：先拉取该企业的岗位列表，确认要采集哪些岗位的投递。

④ 抓取投递与简历

点开始抓取，面板并发拉取投递列表与每份简历详情，进度实时显示。

⑤ 勾选导出内容

选择「仅岗位列表 / 仅投递简历 / 两者都要」，选好目录导出 Excel。

⑥ 查看结果

Excel 冻结首行 + 自动筛选 + 超链接，岗位名/简历名可直接点开对应网页。

实测性能

测试对象规模结果
笨豆腐百姓菜馆（冒烟）3 个岗位 / 28 条投递 / 27 份简历详情约 28 秒完成（含限速 1 请求/秒）
导出组合验证仅岗位列表 / 仅投递简历 / 两者都要三档均正常，文件名自动区分
投递列表抓取岗位投递明细走后台接口，不受前台限速影响，仍为并发
不要把「抓取线程」当加速手段。 前台简历页的速率由「前台请求间隔」决定，线程调到 16 也不会更快，反而更容易触发 WAF 拦截。 调大间隔（例如 1.5 或 2）在长时间批量抓取时更稳。

到 Release 页面下载 ResumeCollector-v1.2.0-windows-x64.exe，放到单独目录双击运行，浏览器会自动打开 http://127.0.0.1:8790。

常见问题

企业搜不到怎么办？

换成企业全称里的关键片段，例如「宝顺」「物流有限公司」。如果关键词太短可能命中很多家，面板会列出结果让你挑选。

为什么有些岗位投递数是 0？

该岗位确实没有收到投递，属正常情况；导出时仍会保留岗位列表。

改了代码后测试拿到的还是旧数据？

多半是端口被上一轮的旧进程占着，新进程绑定失败静默退出。用 netstat -ano | findstr :8790 找到 PID 结束掉，再重启。

电话需要 OCR 吗？

不需要。这个面板拿到的投递人电话是明文（与「简历库」列表接口不同，那里才是图片）。

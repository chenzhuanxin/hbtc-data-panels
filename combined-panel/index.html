城市中国综合数据面板

一个 exe · 一个端口 · 一个门户 —— 平台 7 类数据 + 企业投递简历，装在一起
端口 8795 门户 + 两个内置子面板 配置共享 Windows 单文件 exe

这个项目和前两个项目什么关系

功能没有任何删减，只是把「两个 exe、两个端口、两份配置」变成了「一个 exe、一个端口、一份配置」。

综合面板把 城市中国平台数据面板 与 企业投递简历采集面板 作为两个内置子面板挂在同一个进程里：

入口等价于说明
/门户导航页两个工具的入口卡片，显示各自配置状态
/city/平台数据面板7 类目全量抓取 + 电话图片 OCR + 简历/岗位/企业/用户全量字段补抓
/jd/企业投递简历采集面板企业 → 岗位 → 投递简历 → 完整简历内容
为什么不用两个 exe 就行？当然可以。但两个独立面板各自要填一遍后台 Cookie、总后台 Cookie、保存目录， 换台电脑或 Cookie 过期时得改两处。综合面板里这些只填一次，两个子面板实时共享。

共享配置：一份 config.json 管两个工具

exe 同目录下的 config.json 是两个子面板共用的同一份文件。

配置项默认用途
cookie—后台 Cookie（job.admin.ccoo.cn），供 两个子面板的列表接口 + 简历/岗位/企业详情使用
master_cookie—总后台 Cookie（www.admin.ccoo.cn），仅「注册用户」全量字段需要，可留空
save_dir—导出的默认保存目录
ocr_scale1电话图片 OCR 放大倍数（实测 1 最准）
fetch_workers8列表 / 后台详情并发线程（后台无 WAF，调大即提速）
fetch_resume_detail1平台数据面板：抓类目时是否顺带补抓后台全量字段
resume_detail_limit0平台数据面板：详情条数上限，0 = 不限

两个子面板共用同一份配置的键空间（各自的默认值与另一方的键完全兼容，读写都是「读盘 → 合并 → 写盘」）， 所以在 /city/ 里保存一次，切到 /jd/ 就已经生效，反过来也一样。

数据分开存放，互不干扰：

综合数据面板/ ← exe 所在目录 ├── config.json # 两个子面板共享的配置 ├── 数据_平台面板/ # /city/ 的抓取缓存与 OCR 缓存 │ └── data_cache/ └── 数据_简历面板/ # /jd/ 的投递数据与状态 └── data_cache/

详情抓取机制（v2.0：全面切换后台编辑页）

v2.0 起所有详情都从后台 / 总后台编辑页抓取：不再抓前台网站，不再需要前台 Cookie，也绕开了前台 WAF。

数据详情来源所需 Cookie
简历全量字段job.admin.ccoo.cn/Post/JlEdit?source=1&jlid={jlid}后台 Cookie
岗位全量字段（全职+兼职）job.admin.ccoo.cn/Post/JobEdit?Source=1&id={jobid}后台 Cookie
企业全量字段job.admin.ccoo.cn/Enterprise/CompanyAdd?source=1&companyId={companyId}后台 Cookie
用户全量字段www.admin.ccoo.cn/yunying/users/user_set.asp?id={userId}总后台 Cookie（纯文本，无需 OCR）
  • 不再需要前台 Cookie：简历正文从后台编辑页 JlEdit 直接拿，字段比前台更全。
  • 全并发提速：后台编辑页无前台 nginx WAF，无令牌桶限速、无请求间隔，fetch_workers 默认 8，调大即提速。
  • 失败自动补抓：一轮跑完后，对失败的详情自动再跑 2 轮；need_login 单独统计，Cookie 失效时明确提示。
  • 断点续抓：按锚点列（姓名 / 岗位标题 / 企业名称 / 家乡通ID）判断详情是否已有，「只补缺失」跳过已有、只抓空缺。
  • 覆盖率反馈：结束时报告「详情覆盖 200/200」；覆盖数 = 总行数即拿到全量。
字段空缺不等于抓取失败：200 份全量成功后的真实填充率为——姓名/性别/年龄/自我描述详情 100%、学历 99%、工作经历 1 55%、头像 53%、现居地 45%、教育经历 1 37%、 获得证书 1 15%、语言能力 1 13%。求职者没填哪一项，后台表单里本身就没有那个区块。

使用流程

① 启动 exe

双击 城市中国综合数据面板.exe，控制台会打印三个入口地址并自动打开门户页。

② 进任一子面板填配置

进 /city/ 或 /jd/，填后台 Cookie、总后台 Cookie（可留空）、保存目录，点「保存配置」。填一次即可。

③ 验证 Cookie

「测试连接」验后台；「测试总后台 Cookie」验总后台（用指定用户探测）。需要用户全量字段才必须配总后台 Cookie。

④ 抓取

/city/ 勾选类目抓 7 类数据（自动补后台全量字段）；/jd/ 搜企业后抓投递与完整简历。

⑤ 导出

/city/ 勾选类目导出 xlsx / zip；/jd/ 选择「岗位列表 / 投递简历 / 两者都要」导出。

⑥ 换工具不重填

切到另一个子面板时，Cookie 与保存目录已经就位，直接开抓即可。

方式一：直接运行 exe（推荐）

到 Release 页面下载 CombinedPanel-v2.0.0-windows-x64.exe，放到一个单独目录里双击即可。 首次运行会在 exe 同目录生成 config.json、数据_平台面板/ 与 数据_简历面板/。

方式二：源码运行

# 1) 安装依赖
pip install flask requests beautifulsoup4 lxml rapidocr_onnxruntime openpyxl onnxruntime

# 2) 准备配置（首次）
cd src
copy config.example.json config.json
#   cookie        = 后台 Cookie（两个子面板共用：列表接口 + 简历/岗位/企业详情）
#   master_cookie = 总后台 Cookie（注册用户全量字段，可留空）
#   fetch_workers = 列表/详情并发线程（默认 8）

# 3) 启动
python -X utf8 面板.py
# 门户 http://127.0.0.1:8795/   （平台数据 /city/   企业投递 /jd/）

重新打包 exe

pip install pyinstaller
cd src
python 打包exe.py
# 产物：dist/城市中国综合数据面板.exe
注意：exe 体积约 110 MB，是因为把 RapidOCR 的 onnxruntime 与全部模型文件都打了进去。 打包命令里显式带了三条 --add-data，把门户页与两个子面板的前端一起塞进包内； 子面板通过 DispatcherMiddleware 挂载，各自仍以 / 与 /api/... 的视角工作，互不冲突。

常见问题

端口 8795 被占用怎么办？

面板会自动顺延到 8796、8797、8798。控制台启动信息里会打印实际端口，以它为准。

两个子面板的配置会互相覆盖吗？

不会。两边读的都是「默认值 → 合并磁盘文件」的结果，保存时把合并后的完整对象写回，所以各自的专属键（例如 ocr_scale、fetch_resume_detail）会一直保留。共享的是 Cookie、保存目录与线程这些公共项。

注册用户没有全量字段？

总后台 Cookie 没配或已过期。配好 master_cookie 后点「只补抓用户详情」即可，不必重抓列表。

简历库抓完了，但没有工作经历 / 教育经历？

后台 Cookie 没配或已过期。列表接口本身不含简历正文，补抓详情必须带后台 Cookie 访问编辑页 JlEdit。

测试总后台 Cookie 提示「返回登录页」？

① Cookie 已过期 → 重新登录复制；② 整串很长，可能漏了后半段；③ 粘贴时被换行截断。 另外这条 Cookie 串只能用分号 ; 切分——ccoo=logintime=…&uid=… 这类 Cookie 的 值本身含 &，按 & 拆会把它截断，认证随即失效。面板已按正确规则处理，整串粘贴即可。

能只跑其中一个子面板吗？

能。不进另一个入口就不会触发它的抓取。想彻底分开用，直接下载对应的独立 exe 即可。

两套采集面板 + 一个综合版，一套招聘数据工作流

针对 城市中国 · 湖北通城网（hbtc.ccoo.cn） 招聘后台打造的本地数据工具： 一款把平台 7 大类目数据（含图片电话 OCR 与完整简历字段）整表导出 Excel， 一款顺着「企业 → 岗位 → 投递简历 → 完整简历」把投递明细一网打尽， 还有一个把两者装进同一个 exe 的综合面板（一份配置、一个端口、一个门户）。 均为 Python + Flask 本地服务 + 浏览器界面，打包为 Windows 单文件 exe，双击即用。

Windows 单文件 exe 本地运行 · 数据不上传 简历全量字段 Excel / ZIP 导出 离线 OCR 反爬限速

v1.3.0：简历「全量」问题已修复

如果你之前导出的简历表后半段是空的，看这里。

问题：8 线程快抓 200 份，只成功了 120 份

前台简历详情页前方是 nginx WAF，拦的是累计请求量而不是并发数。 用 8 线程、不限间隔连抓 200 份时，只有 120 份成功、80 份失败， 且失败的全部集中在后半段——导出的表里后 80 行整片空白，看起来就像「只拿到了后台的部分数据」。

修复：限速 + 自动补抓 + 覆盖率反馈

改用 1 请求/秒限速重抓，那 80 份全部成功；200 份全量只用 256 秒， 200/200 全部拿到。v1.3.0 内置：失败自动再补 2 轮、 连拦 3 次自动熔断、中断后点「只补缺失详情」续抓， 并在界面实时显示「当前详情覆盖 120/200」——覆盖数 = 总行数才算全量。

字段空缺 ≠ 抓取失败。200 份全量成功后的真实填充率：姓名/性别/年龄/自我描述详情 100%、学历 99%、工作经历 1 55%、头像 53%、现居地 45%、 教育经历 1 37%、获得证书 1 15%、语言能力 1 13%。求职者没填哪一项，前台页面本身就没有那个区块。

使用方式

两种方式选其一：直接跑 exe，或用源码启动。

1

下载 exe

到 Release 页面下载对应的 .exe 文件，放到任意目录（建议单独建一个文件夹）。

2

双击启动

双击 exe，控制台窗口会自动打开浏览器面板；关闭窗口即停止服务。

3

填账号 / 两种 Cookie

填入后台账号密码或后台 Cookie（管类目与投递列表）。若要完整简历内容，再粘贴前台站点 www.hbtc.ccoo.cn 的 Cookie，各自点「测试」验证。

4

抓取并导出

选择类目 / 企业后开始抓取，完成后勾选需要的类目或工作表导出到指定目录。

为什么需要前台 Cookie？简历的完整正文（工作经历、教育经历、语言能力、获得证书）只存在于前台简历详情页 /post/qiuzhi/{id}x.html，该页不带前台登录 Cookie 会返回登录页。两种 Cookie 分开配置、各管一段。

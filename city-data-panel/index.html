城市中国平台数据面板

城市中国 · 湖北通城网 招聘频道（hbtc.ccoo.cn）后台 7 类数据一键采集与导出
端口 8787 Flask + RapidOCR 简历全量字段补抓 Excel / ZIP 导出 Windows 单文件 exe

这个工具是做什么的

把招聘后台里散落在 7 个菜单下的数据，一次性抓下来、清洗好、按规范格式导出成 Excel。

它启动后是一个本地网页面板（http://127.0.0.1:8787）。你在页面上填好后台账号或 Cookie，点一下就能把 订单、岗位、企业、简历、会员、注册用户等类目全量抓取到本地，再按需要勾选类目导出。 原始接口里有两处「不友好」的地方——电话/手机号是 base64 图片、时间是 /Date(毫秒)/ 格式—— 面板都自动处理掉：图片走离线 OCR 转文字，时间统一成 yyyy-mm-dd hh:mm:ss。

  • 7 类目全量抓取：订单管理、全职岗位、兼职岗位、企业库、会员企业、简历库、注册用户。
  • 电话图片 OCR：简历库的 tel、注册用户的 mobile 是 base64 内嵌图（前缀写 png 实为 JPEG），自动识别成可复制文本。
  • 详情全量字段补抓：列表接口只给摘要，面板按 ID 打开后台编辑页补全——简历 JlEdit（工作经历/教育经历/语言能力/获得证书）、岗位 JobEdit、企业 CompanyAdd、用户 user_set.asp（总后台，纯文本无需 OCR）。
  • 勾选式导出：单类目导出一个 .xlsx，多类目自动打包成一个 .zip，文件名自动带类目与时间戳。
  • 字段完整 + 智能隐藏：保留接口返回的全部字段（两行表头：英文 / 中文），对照参考 Excel 把次要列设为隐藏列。
  • 脏数据清洗：自动剔除 Excel 不支持的控制字符（如昵称里的 \x0e 之类），超长文本截断到 32767 字符。
  • 并发抓取：分页并发拉取（默认 6 线程，可配置），9.8 万条数据也能较快完成。

使用流程

① 填登录信息

在「配置」区填写后台账号密码，或直接粘贴登录后的后台 Cookie（job.admin.ccoo.cn）。点「测试」验证是否仍有效。

② 填总后台 Cookie

想连注册用户全量字段一起抓，再粘贴总后台 www.admin.ccoo.cn 的 Cookie，点「测试总后台 Cookie」验证（可留空）。

③ 开始抓取

点击「开始抓取」，面板会并发分页拉取全部类目；勾选「同时补全后台全量字段」后自动按 ID 打开编辑页补抓详情。

④ 浏览与筛选

抓取完成后可在页面按类目查看数据、翻页、关键字过滤（可按简历库的姓名 / 现居地 / 期望职位筛选）。

⑤ 勾选导出

在导出区勾选类目（支持全选/全不选/反选/只选已抓取），选择保存目录后导出。

只想补抓详情？列表已经抓过了，不用重跑。在各行点「只补缺失」按钮即可： 它会复用已有列表，按 ID 打开后台编辑页补抓详情并回写缓存。若只想试抓一小批，把「详情条数上限」填成 40 之类的数字即可， 留 0 表示不限。

简历库的「全量简历内容」是怎么拿到的（v2.0）

v2.0 起，简历详情改从后台编辑页抓取：不再抓前台网站，不再需要前台 Cookie。

简历库列表接口 /Post/GetPostJlList 返回的是列表级字段——姓名性别年龄、学历、期望职位、 电话图片等等，够做筛选和统计，但不含简历正文。完整的简历（工作经历、教育经历、语言能力、获得证书） 存在于后台编辑页：

http://job.admin.ccoo.cn/Post/JlEdit?source=1&jlid={简历ID}

该页是服务端渲染的完整简历表单，携带后台 Cookie（cookie）即可访问，字段比前台更全。 v2.0 全面切换为后台编辑页后，不再需要前台站点 Cookie，也没有前台 nginx WAF，抓取为全并发。

同理，其他类目也一并切到后台编辑页：岗位（全职+兼职）→ /Post/JobEdit?Source=1&id={岗位ID}； 企业 → /Enterprise/CompanyAdd?source=1&companyId={企业ID}； 注册用户 → 总后台 www.admin.ccoo.cn/yunying/users/user_set.asp?id={用户ID}（纯文本表格，无需 OCR）。

总后台 Cookie 怎么取？浏览器登录 http://www.admin.ccoo.cn → 按 F12 → Network → 点任意请求 → 复制 Request Headers 里的整条 Cookie → 粘到面板「总后台 Cookie」框 → 点「测试总后台 Cookie」 （面板用指定用户探测，返回用户名/注册IP等即通过）。总后台 Cookie 仅「注册用户」全量字段需要，可留空。

坑一（务必知道）：Cookie 串只能用分号 ; 切分，不能按 & 切。 站点里 ccoo=logintime=…&uid=…、ccoocitycrm=pass&crm_username=… 这些 Cookie 的 值本身就含 &，按 & 拆会把它们截断，认证随即失效，页面又变回登录页。

坑二：本机若开着代理软件（例如把 127.0.0.1 也走了代理），请求会被劫持成 502。 面板给每个线程单独建了 requests.Session 并关闭环境代理（trust_env = False），避免这个干扰。

后台详情补抓机制（v2.0）

  • 全并发抓取：后台编辑页无前台 WAF，不再需要令牌桶限速 / 请求间隔；fetch_workers 默认 8，调大即提速。
  • 失败自动补抓：一轮跑完后，对失败的详情自动再跑 2 轮，直到抓全。
  • need_login 单独统计：Cookie 失效导致的失败单独统计并明确提示，而不是混在普通失败里。
  • 只补缺失详情：中断后点这个按钮，跳过已有详情、只抓空缺的那些，不必重跑已有部分。
  • 结果落盘：抓完直接回写 data_cache/简历库.json，下次导出无需重抓。
怎么确认「拿到了全量」：补抓结束时面板会直接报告覆盖率，例如 「简历详情 成功 200 / 失败 0，详情覆盖 200/200」；抓取过程中也实时显示 「当前详情覆盖 120/200」。覆盖数 = 总行数就说明每一份都取到了后台详情。 若提示 need_login，说明 Cookie 失效，重新粘贴后点「只补缺失详情」续抓即可。
字段空缺不等于抓取失败：200 份全量成功后的真实填充率为——姓名/性别/年龄/自我描述详情 100%、学历 99%、工作经历 1 55%、头像 53%、现居地 45%、教育经历 1 37%、 获得证书 1 15%、语言能力 1 13%。求职者没填哪一项，后台表单里本身就没有那个区块。

几个关键实现细节

电话 / 手机号图片 OCR

简历库 tel、注册用户 mobile 字段返回的是 base64 字符串，解码后其实是 JPEG 图片。 面板内置 RapidOCR（onnxruntime 离线推理）识别。经过真值对比测试：按原始尺寸识别最准（39/40）， 放大图片反而会识别失败——这一点和很多人「放大 10 倍更准」的旧经验相反，所以面板里放大倍数默认 1，并保留为可配置项。 识别结果会写入本地 data_cache/ocr_cache.json 缓存，重复抓取不必重新识别。

时间字段统一格式化

接口返回的时间是 .NET 风格的 /Date(1735689600000)/ 以及毫秒数值（birthday 等）。 面板统一转换为 yyyy-mm-dd hh:mm:ss（东八区），并把 .NET 最小值 -62135596800000 转成空值。

并发分页抓取

按页并发请求（ThreadPoolExecutor，默认 6 线程），按页序流式消费避免内存暴涨； 单页失败重试 3 次，每 20 页落盘一次；如果接口返回的 count 偏小，会自动顺序补拉剩余页。

Excel 导出与非法字符清洗

导出用 openpyxl 的 write_only 模式（大表也省内存）。写单元格前会统一清洗 Excel 不允许的 XML 控制字符（正则 [\000-\010]|[\013-\014]|[\016-\037]）， 并把超过 32767 字符的文本截断。实测全量 98,657 行中只有「注册用户」的 nick 字段命中 2 行， 导出完成后会提示「已自动清洗 N 处非法字符 / 超长文本」。

后台编辑页的解析要点

详情页均为服务端渲染的 HTML 表单/表格：简历 JlEdit、岗位 JobEdit、企业 CompanyAdd 是 <td> 标签 → 下一 <td> 值的结构，按字段标签定位取值； 用户 user_set.asp 是 td.align=right 标签 → 下一 td 值的表格结构， 注册IP 值形如 117.154.28.195[查看IP所在地]（自动去掉 [...] 后缀）、 会员年龄 31岁（生日：1995/1/1）（自动拆出年龄+生日）、 会员服务 8 项状态（房屋中介/名企招聘/论坛登录/车行/二手商家/新楼盘管理/分类信息发布/微信登录）逐项合并。 正文里的 <br> 统一转成换行、并反转义 HTML 实体，保证 Excel 里是可读的多行文本。

头像 / 照片的占位图识别

部分简历没有真实头像，页面会输出占位图。占位图的文件名存在 offer-list-autor.png 与 offer-list-autor1.png 两种拼写，只判断带 1 的那种会漏判。 现在统一按 offer-list-autor 前缀 + 其它若干占位关键字（nophoto / noavatar / touxiang_moren 等）过滤，避免把占位图当成真实头像导出去。

导出区勾选状态

勾选状态用的是独立的 Set 数据源而不是直接读 DOM，所以后台轮询刷新时不会把用户已选类目重置； 新抓取完成的类目会自动补勾，其余选择一律保留。

常见问题

端口 8787 被占用怎么办？

面板会自动顺延到 8788、8789…。如果你点了旧实例的页面又发现数据对不上，多半是「旧进程占着 8787、新进程跑在 8788」。 排查：netstat -ano | findstr :8787 找到 PID 后结束进程，再重新启动。

提示登录失效 / 返回登录页？

Cookie 有时效。在面板里重新登录一次，或粘贴最新的 Cookie，点「测试」确认通过后再抓取。

简历库抓完了，但没有工作经历 / 教育经历？

那是后台 Cookie 没配（或已过期）。列表接口本身不含简历正文，补抓详情必须带后台 Cookie 访问编辑页 JlEdit。 配好后点简历库行的「只补缺失」，不必重新抓列表。

注册用户抓完了，但没有全量字段？

那是总后台 Cookie 没配（或已过期）。用户全量字段来自总后台 user_set.asp，配好 master_cookie 后点「只补缺失」即可，无需重抓列表。

测试总后台 Cookie 报错？

三种常见原因：① Cookie 已过期，重新登录复制；② 复制时漏了后半段（整串很长，注意别只复制到分号处）； ③ 粘贴时被换行 / 空格截断——面板会自动去掉首尾空白并按分号重组，但仍建议整串一次性粘贴。 若你的电脑开着代理，请确认 127.0.0.1 未被代理接管（面板已尽量规避）。

OCR 识别不准？

保持 ocr_scale = 1（默认）。如需调整可在配置里改放大倍数，但实测放大往往更差。

导出时提示非法字符？

这是源数据本身含 Excel 不接受的不可见控制字符，面板已自动清洗并在导出完成消息里告知清洗数量，无需人工处理。

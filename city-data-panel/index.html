这个工具是做什么的

把招聘后台里散落在 7 个菜单下的数据，一次性抓下来、清洗好、按规范格式导出成 Excel。

它启动后是一个本地网页面板（http://127.0.0.1:8787）。你在页面上填好后台账号或 Cookie，点一下就能把 订单、岗位、企业、简历、会员、注册用户等类目全量抓取到本地，再按需要勾选类目导出。 原始接口里有两处「不友好」的地方——电话/手机号是 base64 图片、时间是 /Date(毫秒)/ 格式—— 面板都自动处理掉：图片走离线 OCR 转文字，时间统一成 yyyy-mm-dd hh:mm:ss。

  • 7 类目全量抓取：订单管理、全职岗位、兼职岗位、企业库、会员企业、简历库、注册用户。
  • 电话图片 OCR：简历库的 tel、注册用户的 mobile 是 base64 内嵌图（前缀写 png 实为 JPEG），自动识别成可复制文本。
  • 简历全量字段补抓：列表接口只给「简历摘要」，面板再逐份打开前台简历详情页，把工作经历、教育经历、语言能力、获得证书等完整内容补进同一张表（简历库 91 列 → 116 列）。
  • 勾选式导出：单类目导出一个 .xlsx，多类目自动打包成一个 .zip，文件名自动带类目与时间戳。
  • 字段完整 + 智能隐藏：保留接口返回的全部字段（两行表头：英文 / 中文），对照参考 Excel 把次要列设为隐藏列。
  • 脏数据清洗：自动剔除 Excel 不支持的控制字符（如昵称里的 \x0e 之类），超长文本截断到 32767 字符。
  • 并发抓取：分页并发拉取（默认 6 线程，可配置），9.8 万条数据也能较快完成。

使用流程

① 填登录信息

在「配置」区填写后台账号密码，或直接粘贴登录后的 Cookie。点「测试」验证是否仍有效。

② 填前台 Cookie

想连简历完整内容一起抓，就再粘贴前台站点 www.hbtc.ccoo.cn 的 Cookie，点「测试前台 Cookie」验证。

③ 开始抓取

点击「开始抓取」，面板会并发分页拉取全部类目；勾选「同时补抓简历详情」后简历库会自动续抓前台内容。

④ 浏览与筛选

抓取完成后可在页面按类目查看数据、翻页、关键字过滤（可按简历库的姓名 / 现居地 / 期望职位筛选）。

⑤ 勾选导出

在导出区勾选类目（支持全选/全不选/反选/只选已抓取），选择保存目录后导出。

只想补简历详情？列表已经抓过了，不用重跑。在简历库那一行点「只补抓简历库详情」按钮即可： 它会复用已有列表，仅逐份补抓前台简历内容并回写缓存。若只想试抓一小批，把「详情条数上限」填成 40 之类的数字即可， 留 0 表示不限。

简历库的「全量简历内容」是怎么拿到的

这是 v1.1.0 的主要改动：列表接口只能给摘要，完整简历得换一条路取。

简历库列表接口 /Post/GetPostJlList 返回的是列表级字段——身份证式的姓名性别年龄、学历、期望职位、 电话图片等等，够做筛选和统计，但不含简历正文。真正的完整简历（做过哪些公司、什么时间段、读了什么学校、 有什么证书和语言能力、自我描述全文）只存在于前台简历详情页：

http://www.hbtc.ccoo.cn/post/qiuzhi/{简历ID}x.html

这个页面是服务端渲染的完整简历，但它必须带前台站点的登录 Cookie：不带 Cookie（或只带后台 Cookie）会返回一个约 22 KB 的登录页，里面没有任何简历内容——这就是「拿到了列表、却没有简历全量数据」的根因。 所以面板把两种 Cookie 分开配置：后台 Cookie 管 7 个类目的接口，前台 Cookie 只管逐份打开简历详情页。

前台 Cookie 怎么取？浏览器登录 http://www.hbtc.ccoo.cn → 按 F12 → Network → 点任意请求 → 复制 Request Headers 里的整条 Cookie → 粘到面板「前台 Cookie」框 → 点「测试前台 Cookie」。 面板会用一份真实简历探测，返回「姓名 + 若干字段」即通过。

坑一（务必知道）：这条 Cookie 串只能用分号 ; 切分，不能按 & 切。 站点里 ccoo=logintime=…&uid=…、ccoocitycrm=pass&crm_username=… 这些 Cookie 的 值本身就含 &，按 & 拆会把它们截断，认证随即失效，页面又变回登录页。

坑二：本机若开着代理软件（例如把 127.0.0.1 也走了代理），请求会被劫持成 502。 面板给每个线程单独建了 requests.Session 并关闭环境代理（trust_env = False），避免这个干扰。

实测性能

  • 并发抓详情：默认 8 线程（可在配置里 1–16 调整，fetch_workers）。
  • 单份耗时：平均约 1.4 s/份（含少量长尾）。
  • 实测：40 份 2 秒完成（0 失败）；30 份在 16 线程下 1.4 秒（约 22 份/秒）。
  • 失败重试：单份自动重试 3 次；整批结束会汇总「成功 / 失败 / 需登录」三个计数。
  • 结果落盘：抓完直接回写 data_cache/简历库.json，下次导出无需重抓。
提示：15,733 份简历全量补抓会产生较多请求。建议先用「详情条数上限」小批量试跑，确认前台 Cookie 有效、 字段解析正常后，再留 0 跑全量。

几个关键实现细节

电话 / 手机号图片 OCR

简历库 tel、注册用户 mobile 字段返回的是 base64 字符串，解码后其实是 JPEG 图片。 面板内置 RapidOCR（onnxruntime 离线推理）识别。经过真值对比测试：按原始尺寸识别最准（39/40）， 放大图片反而会识别失败——这一点和很多人「放大 10 倍更准」的旧经验相反，所以面板里放大倍数默认 1，并保留为可配置项。 识别结果会写入本地 data_cache/ocr_cache.json 缓存，重复抓取不必重新识别。

时间字段统一格式化

接口返回的时间是 .NET 风格的 /Date(1735689600000)/ 以及毫秒数值（birthday 等）。 面板统一转换为 yyyy-mm-dd hh:mm:ss（东八区），并把 .NET 最小值 -62135596800000 转成空值。

并发分页抓取

按页并发请求（ThreadPoolExecutor，默认 6 线程），按页序流式消费避免内存暴涨； 单页失败重试 3 次，每 20 页落盘一次；如果接口返回的 count 偏小，会自动顺序补拉剩余页。

Excel 导出与非法字符清洗

导出用 openpyxl 的 write_only 模式（大表也省内存）。写单元格前会统一清洗 Excel 不允许的 XML 控制字符（正则 [\000-\010]|[\013-\014]|[\016-\037]）， 并把超过 32767 字符的文本截断。实测全量 98,657 行中只有「注册用户」的 nick 字段命中 2 行， 导出完成后会提示「已自动清洗 N 处非法字符 / 超长文本」。

简历详情页的解析要点

前台简历页里「工作经历 / 教育经历 / 语言能力 / 获得证书」四个区块用的是同一个 class （j-work-module clearfix step-circle），直接按 class 抓会把证书、语言块当成工作经历 （实测出现过「工作经历6 = 心理健康指导」这种错位）。所以解析时先按小节标题 <p class="j-tit-module">工作经历</p> 定位到区块，再只在区块内匹配条目。 另外两处细节：时间段节点本身已自带括号，要避免再包一层变成 （（2019.6-2020.8））； 正文里的 <br> 统一转成换行、并反转义 HTML 实体，保证 Excel 里是可读的多行文本。

头像 / 照片的占位图识别

部分简历没有真实头像，页面会输出占位图。占位图的文件名存在 offer-list-autor.png 与 offer-list-autor1.png 两种拼写，只判断带 1 的那种会漏判。 现在统一按 offer-list-autor 前缀 + 其它若干占位关键字（nophoto / noavatar / touxiang_moren 等）过滤，避免把占位图当成真实头像导出去。

导出区勾选状态

勾选状态用的是独立的 Set 数据源而不是直接读 DOM，所以后台轮询刷新时不会把用户已选类目重置； 新抓取完成的类目会自动补勾，其余选择一律保留。

常见问题

端口 8787 被占用怎么办？

面板会自动顺延到 8788、8789…。如果你点了旧实例的页面又发现数据对不上，多半是「旧进程占着 8787、新进程跑在 8788」。 排查：netstat -ano | findstr :8787 找到 PID 后结束进程，再重新启动。

提示登录失效 / 返回登录页？

Cookie 有时效。在面板里重新登录一次，或粘贴最新的 Cookie，点「测试」确认通过后再抓取。

简历库抓完了，但没有工作经历 / 教育经历？

那是前台 Cookie 没配（或已过期）。列表接口本身不含简历正文，补抓详情必须带前台站点的登录 Cookie。 配好前台 Cookie 后，点简历库行的「只补抓简历库详情」，不必重新抓列表。

前台 Cookie 测试提示「返回登录页」？

三种常见原因：① Cookie 已过期，重新登录复制；② 复制时漏了后半段（整串很长，注意别只复制到分号处）； ③ 粘贴时被换行 / 空格截断——面板会自动去掉首尾空白并按分号重组，但仍建议整串一次性粘贴。 若你的电脑开着代理，请确认 127.0.0.1 未被代理接管（面板已尽量规避）。

OCR 识别不准？

保持 ocr_scale = 1（默认）。如需调整可在配置里改放大倍数，但实测放大往往更差。

导出时提示非法字符？

这是源数据本身含 Excel 不接受的不可见控制字符，面板已自动清洗并在导出完成消息里告知清洗数量，无需人工处理。
